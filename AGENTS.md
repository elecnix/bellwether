# Working in this repo

Bellwether is the agent-supervision tool described in the design at `/Users/nicolas/design/bellwether.html`. Read that first. It carries the decisions, the references and the phase plan.

The [README](README.md) is for a person deciding whether to use Bellwether, and `docs/` is for one who has decided. Keep the README to its five questions, and put any detail a user needs into the topic file under `docs/` that covers it.

## Parts and their roles

A parent session runs an adapter: the Pi extension in `src/integrations/pi/`, or the Claude Code MCP channel server in `src/integrations/claude/`. Adapters share the tool list in `src/integrations/tools.ts` and talk to one daemon per machine. Whichever session needs the daemon first starts it detached. It exits once no session stays connected, and no parent's daemon on another machine stays connected through `bellwether relay-bridge`.

- **Daemon** (`src/daemon/`). It listens on a socket under the Bellwether home, and it is the only process with state. That state covers the registry and the outbox, the relay outbox, and the herdr subscriptions. It starts without the identity variables of the session that launched it. A lock file (`daemon.lock`, which also records the version, protocol and entry point) keeps a second daemon from starting, so the machine has one daemon for all its children. A client from a newer release, compared by package version and then by protocol, hands the daemon over (`src/daemon/handover.ts`). It first holds `daemon.starting`, so other clients wait. Then it drains the old daemon, which stops taking connections and exits once its calls in flight answer. It waits for the lock to go, and starts its own daemon. Each session connected before the hand-over reconnects to the new daemon, because a daemon also serves `MIN_CLIENT_PROTOCOL`, the protocol before its own. A client from an older release never replaces a newer daemon. `bellwether drain` drains by hand, `bellwether daemon` runs one in the foreground, and `bellwether doctor` reports where an upgrade stands. [docs/upgrading.md](docs/upgrading.md) gives what a person sees.
- **herdr client** (`src/core/herdr-client.ts`). Newline-delimited JSON on the herdr socket, one connection per request and one held open for the subscription. The subscription waits for the `subscription_started` acknowledgement, and keeps any event that arrives in the same read.
- **Registry** (`src/core/registry.ts`). One JSON file per parent session under `~/.bellwether/parents/`, written only by the daemon. A child record stores its name, kind, host, pane, tab, start time, last status, last `completion_seq`, harness session and transcript path, and keeps them after the child exits. A file written before registry version 2 gains `host: local` on its next write.
- **Watcher** (`src/core/watcher.ts`). It subscribes to `pane.agent_status_changed` for each child pane, plus `pane.exited`, `pane.closed` and `pane.agent_detected`. On connect it subscribes first, reads a snapshot on a second connection, then reconciles. A dropped subscription reconnects with backoff and takes a fresh snapshot. It also sends the answer to a resumed Claude Code session's startup dialog, and starts retirement when a pane exits.
- **Classifier** (`src/core/classifier.ts`). A pure function of state, clock and observation that turns herdr states into child events, each with its settle time. An open dialog counts as `blocked` whatever herdr reports, and it holds back `idle`, `stuck` and `inactive`. [docs/tools.md](docs/tools.md) lists the events.
- **Dialogs** (`src/core/modal.ts`). herdr reports a pi child on an extension's dialog as `idle`. The child's pi extension sends pi's `ui_prompt_start` and `ui_prompt_end` to the daemon as `child_prompt`, which records the dialog on the child record. For any other harness, the watcher reads the screen once before an `idle` event, and `detectModal` names the dialog in one line. Bellwether reports a dialog and never answers it, apart from Claude Code's startup questions.
- **Outbox** (`src/core/outbox.ts`). One pending entry per child, where a newer state replaces an older one. At delivery, an unread `blocked` or `stuck` entry drops out once the child has moved on. The adapter marks an entry read when its own message with the receipt enters the parent's conversation. The outbox file stores the read flag and the delivery time with each entry, so a restarted daemon replays only the unread entries, oldest event first. `src/core/notice.ts` orders a backlog by event time and adds a note to an event that arrives more than a minute late.
- **Relay** (`src/daemon/relay-links.ts`, `src/daemon/relay.ts`, `src/core/relay-records.ts`, `src/core/ssh.ts`). The parent's daemon keeps one SSH connection open to each machine that runs one of its children. That connection runs `bellwether relay-bridge` there, and the daemon collects the reports that wait in that machine's relay outbox. [docs/remote-machines.md](docs/remote-machines.md) describes the connection, its states and the refusals.
- **Move** (`src/core/move.ts`, `src/core/move-plan.ts`, `src/core/move-endpoint.ts`, `src/core/session-state.ts`). `agent_move` copies a child's harness session to another machine and checks the copy. It then stops the source tab and resumes the session there under the same child id. When the start fails, it starts the child again on the source. The decisions are pure functions in `move-plan.ts`. Each machine computes its own session paths in `session-state.ts`, which the daemon calls directly for its own machine and through `bellwether move-*` over SSH for another. [docs/moving.md](docs/moving.md) lists the refusals and the order.
- **Spawn, resume, restart and retire** (`src/core/spawn.ts`, `src/core/spawn-resume.ts`, `src/core/restart.ts`, `src/core/retire.ts`). Spawn writes the record, the brief and a Claude child's MCP config, then opens the tab and sends the answers to the startup dialogs. Resume holds a per-child lock under `~/.bellwether/locks/` while herdr decides between a message and a new tab. Retirement records `retireStage` after each removal, so a restarted daemon finishes it without repeating a step. [docs/recovery.md](docs/recovery.md) gives the behavior a user sees.

Each adapter sends its session's identity with every call: the herdr pane it runs in, and the child id its spawn gave it. The daemon resolves that identity against its child records, so a `parent_report` goes to the parent whose registry lists the child, whichever process made the call. When no record matches, the error gives the pane and the path of the MCP config file the spawn should have written.

The Claude Code server speaks MCP over stdio, so every log line goes to stderr and stdout carries only the protocol. It exits when stdin closes.

## Layout

```
src/core/          herdr client, registry, watcher, classifier, outbox, spawn, resume, retire, relay records
src/daemon/        the daemon: protocol, server, client, lock, relay, parent service
src/integrations/  the tool list, shared by both adapters, with pi/ and claude/
bin/               the bellwether command and MCP server, run from the sources in a checkout
dist/              the compiled JavaScript that npm publishes, built by `npm run build`
scripts/           the release script, the site build and the phase 0 probe scripts
docs/              user topics, probe results and test briefs
site/              the documentation site's page template and stylesheet
test/unit/         tier 1
test/integration/  tier 2: a fake herdr socket and the daemon
test/lab/          tier 3: a real isolated herdr server
```

## Gates

Run these before a pull request. CI runs the same commands.

```sh
npm run typecheck      # tsgo over src, test, bin
npm test               # tier 1 unit, then tier 2 and 3 integration
npm run doctor         # bellwether doctor against the live herdr
```

The documentation site on GitHub Pages comes from `README.md` and the topic files under `docs/`. `npm run site` writes it to `_site/`, and the `pages` workflow deploys it from `main`. A new topic file reaches the site once it has an entry in `PAGES` in `scripts/build-site.ts`.

A release ends only when the deployed site's byline shows the released version, and `npm run release` checks it. Locally, `npm run site` fails on a page whose byline shows a version other than the one in `package.json`.

Prose in Markdown files runs through Vale. The rules are the `ai-tells`, `ai-tells-experimental` and `noslop` packs. Read `/Users/nicolas/.agents/skills/vale-prose-rules/SKILL.md` before writing docs, a pull request body or a ticket.

## Rules that are not style

- **A session talks to the daemon, not to herdr.** The daemon reads the herdr subscription and stores the registry and outbox for every session on the machine. A tool call from an adapter goes to the daemon, and the daemon sends the adapter its events.
- **Never poll herdr for status.** Status arrives on `events.subscribe`. The only timers are the classifier's settle times and the stuck threshold.
- **Subscribe before the snapshot.** herdr does not replay events, so a subscription opened after a snapshot misses whatever happened between the two.
- **Write the registry record before `tab.create`.** A crash mid-spawn must still leave a trace.
- **Pass the brief through a file.** Each spawn writes it to `~/.bellwether/prompts/<child id>.md` with mode 0600, and the harness gets one line that points at it. herdr refuses an argument with a line break, and a command line shows in `ps`. A spawn that fails removes its record, its brief and its tab, so the parent hears nothing about a child that never ran. A child on another machine gets its brief on that machine: the spawn sends the text on the standard input of `bellwether relay-register` there, and points the harness at that copy. When the copy fails, the spawn fails before it opens a tab. The child's exit, `agent_stop` and a failed spawn remove the copy with `bellwether relay-cleanup`.
- **The daemon keeps the state, and every adapter is a client of it.** The daemon keeps the registry, the outbox and the herdr subscriptions for every session on the machine. An adapter, the Pi extension or a Claude Code MCP server, holds none of them. It sends its identity with every call, as its herdr pane and its child id, and the daemon resolves that against the child records it holds. Never read a parent or a child id from the daemon's own environment, which belongs to whichever session started it.
- **Give each Claude Code child its own MCP server.** The spawn writes `~/.bellwether/mcp/<child id>.json` with mode 0600 and passes it as `--mcp-config=<file>`. The file lists one server, which runs the packaged channel entry with `--child <child id>`. A resume writes it again for the same child id. A child that exits, or whose spawn fails, takes the file with it, as it takes its brief. A child on another machine gets its file from that machine: the spawn runs `bellwether relay-register` there over SSH, which writes the file and a relay record. The relay record has no address for the parent's machine.
- **Give each pi child the extension from the running package.** The spawn passes `-e <file>` for the pi extension inside the package that runs the spawn, and sets `BELLWETHER_PI_EXTENSION` to the same file in the tab. A child needs its tools even on a machine whose pi has no Bellwether package. A copy of the extension from the host's pi settings sees the variable and the matching `-e`, so it registers nothing. A spawn that cannot find the file fails before it opens a tab, and the error gives the file name. A child on another machine loads that machine's file, which `bellwether relay-register` prints. So a failed registration fails a pi spawn, while a Claude Code spawn still starts. An older copy in pi's settings has no guard and makes pi exit on the duplicate tools. While pi's settings list one, the spawn refuses and tells the operator to run `pi install npm:@elecnix/bellwether`. The test preload sets `PI_CODING_AGENT_DIR` to a scratch directory, so no case reads the operator's pi settings.
- **Give a pi child its parent's provider and model.** The pi adapter sends the session's current pair with each tool call, and the spawn passes it as `--provider` and `--model` unless the caller names both. Half a pair fails the spawn before the record, because pi would match it with whatever provider it defaults to. With the pair unknown, the spawn passes neither flag. The reply then gives the provider account that pi chose, read from the child's session file, or until that file exists, the default that pi's settings point to, marked unverified.
- **Answer Claude Code's startup dialogs for the person.** Each Claude Code child opens on the development-channel confirmation, because Claude Code loads a `server:` channel only under `--dangerously-load-development-channels`, and that flag always asks. A folder Claude Code has not seen also asks the folder-trust question. The spawn answers both, saying yes to the trust question for any folder, because the operator approves every spawn by default. It moves the selection toward the accepting option and sends Enter only once the screen shows that option selected. A dialog still on screen after 30 s fails the spawn, with an error that specifies the dialog. While the spawn answers, `startingUntil` on the child record stops the watcher from reporting the child. When a resumed session shows a startup dialog later, the watcher answers it and does not publish a `blocked` event.
- **The daemon is the reaper.** A child asks the daemon to retire it with `request_retirement`, which records the intent and doesn't remove anything. The watcher cleans up once herdr reports the pane gone, through `src/core/retire.ts`. It refuses unless the worktree is clean and not a main worktree, the default branch or a settled pull request holds its work, and no process works inside it. Never add a separate reaper process, a timer or a witness for it. A child Bellwether adopted, a child on another host, and any main worktree are out of bounds.
- **The daemon is the restarter.** `agent_restart` runs in the daemon, which keeps running after every client stops. A session that restarts itself gets its reply first, and the daemon acts once its turn ends. The request is a field on the record, so a daemon that stops mid-wait arms it again when the session's service starts. Each restart closes the old pane before it starts the new one, so one process runs a session at a time and the person has no old pane to close. For a child, the daemon closes only a pane Bellwether started, and the child comes back in a new tab under the same child id. A parent session's pane closes only when herdr reports the same session id there. The daemon refuses a live agent missing from every registry. An act that began runs to the end, even after closing the caller's pane stops the caller's service. No separate process takes part, and no timer runs beyond the bounded wait.
- **The parent dials out, and the child waits.** The parent's daemon keeps the registry of record. For each machine that runs one of its children, it keeps one SSH connection open. That connection runs `bellwether relay-bridge` there and subscribes the daemon to the reports that wait in that machine's relay outbox. A child's daemon writes each such report to disk. It hands the report to a connected parent's daemon, and it deletes its copy only once that daemon acknowledges it. The parent's daemon accepts each receipt once. After a lost connection, it retries with backoff. `bellwether doctor`, the log, `agent_list` and the inactivity notice all show the state it keeps for each machine. `agent_read` for a remote child goes over the same connection. Never add a connection from the child's machine to the parent's. Use the operator's SSH configuration as it stands, and don't write anything under `~/.ssh`.
- **Use an API before the pane.** When herdr, the harness or its files offer the state Bellwether needs, such as a status event or a transcript, read it there. Reading a pane, or typing into one, is a last resort, because a pane is a rendering of state rather than the state itself, and what it accepts depends on which program holds the foreground. Showing a person a child's screen, as `agent_read` does, is a feature. Reading the screen as evidence for a decision the daemon makes, or typing into a pane when no parent asked, is a fallback. Put a `TODO(api):` comment above each fallback, and in it specify the API, or the change to an API, that would retire it. Put a `Pane feature:` comment above each feature, saying who reads the screen or who asked for the keys. `test/unit/pane-fallbacks.test.ts` fails on a pane read or keystroke with neither comment.
- **Send input only to panes this parent started.** A parent must never type into a pane it does not own.
- **Wake the parent through its harness.** `pi.sendMessage(..., {triggerTurn: true, deliverAs: 'steer'})` for Pi, `notifications/claude/channel` for Claude Code. Never type into the parent's own pane. A busy pi session takes a steered message after the tool calls in flight, before its next model call. `followUp` holds the message until the whole run ends, and one live run left events nearly five minutes late.
- **A delivery marks an event read.** Sending a notification does not prove a turn started. For pi, the proof is the extension's own message, with the receipts in its `details`, at `message_end`. For Claude Code, it is an `attachment` line whose origin is the Bellwether channel. A receipt in a tool result, such as the output of a shell that read the outbox file, leaves the event unread, so a parent that inspects its outbox still gets the notification.
- **Tests run Bellwether on a socket and home of their own.** Every test script loads `test/fixtures/isolation.ts` with `--import`. It sets `BELLWETHER_HOME` and `BELLWETHER_DAEMON_SOCKET` under a temporary root, and throws when a test connects to or listens on anything under the live `~/.bellwether`. `test/unit/isolation.test.ts` fails when a script drops the preload. A test that touches the live daemon or the real registry is a defect.
- **Install the tool a check needs.** Vale, `gh`, `jq` and the rest are part of the work, not an excuse to skip it. Take the version that the dotfiles pin with `mise`, which is how this machine gets Vale 3.20.0, and on a machine without mise install that same release by hand. When an install cannot happen, name what blocked it in the pull request and leave the check failing. A missing binary never counts as a pass.

## Test tiers

`npm test` runs all three tiers. Each has its own npm script, and the briefs behind them sit in `docs/test-briefs/`.

1. **Unit.** `test/unit/daemon-protocol.test.ts` covers the daemon wire format. `test/unit/classifier.test.ts` drives the settle times with a hand-picked clock. `test/unit/outbox.test.ts` covers merging and receipts against a scratch home. `test/unit/registry.test.ts` covers persistence. `test/unit/release.test.ts` drives `scripts/release.ts` against a scripted npm, git and gh, one case per stage a run can resume from. Each case takes its clock and its directory as an argument.
2. **Fake socket.** `test/fixtures/fake-herdr.ts` is a Unix socket server that speaks the newline-delimited protocol, and `test/fixtures/herdr-methods.ts` refuses an unknown method or a missing field. `test/integration/daemon.test.ts` covers one service per parent, event fan-out, replay after a reconnect, bye, drain and the idle exit. `test/integration/handover.test.ts` copies these sources as an older release with `test/fixtures/installs.ts`, and runs both releases' daemons as real processes on one home. It covers a hand-over with a session of the older release still connected, an older session that uses a newer daemon and leaves it running, a call in flight at the drain that still gets its answer, and a hand-over after a crash on either side, with doctor's verdict at each step. `test/integration/watcher.test.ts` covers the text a parent receives for a child event. `test/integration/blocked-modal.test.ts` covers a child on a dialog that herdr calls idle, named by pi or from the screen, a child that answers its dialog and sends one `idle` at the end of its turn, and a child at its prompt that reads `idle`. Each case fails when the fake herdr records a keystroke sent to the pane. `test/integration/startup-dialogs.test.ts` plays Claude Code's two startup dialogs in a scripted pane, and shows the spawn answering them with nothing published, a dialog that never goes away failing the spawn by name, and a stale `blocked` entry dropped at delivery. `test/integration/retire.test.ts` drives retirement with the fake git in `test/fixtures/fake-git.ts`, and `test/unit/retire-git.test.ts` runs the real git operations against a scratch repository. `test/integration/remote-report.test.ts` joins two Bellwether homes with the fake ssh in `test/fixtures/fake-ssh.ts`, which streams a long-lived connection, cuts it on demand and refuses one. It covers a report delivered once over an open connection, a report from an outage delivered once on reconnect, a receipt that arrives twice, a child machine that never runs ssh, `doctor` through a drop and a reconnect, `agent_read` over the open connection, a spawn that registers its child on the other machine and copies its brief there, and a spawn that fails when the brief copy fails. `test/integration/pi-launch.test.ts` covers a pi child's `-e` argument, a spawn whose extension is missing, the session path that herdr reports after the spawn, `agent_read` from that file, and the name a pi child gives itself. `test/integration/move.test.ts` moves a child between two fake machines in both directions. It covers the copy and its verification, the resume on the target, a failed resume that rolls back to the source, and the refusals for a missing pi pair, a missing harness and a session already at the target path. `test/unit/move-plan.test.ts` covers the refusal matrix, the target paths for both harnesses and the rollback decision. `test/integration/transcript-record.test.ts` follows the transcript path on a Claude child's record through a spawn, the watcher, an exit and a resume. When the file is absent, the record leaves the path out and says why. `test/integration/notification-delivery.test.ts` runs the pi extension against a daemon whose service keeps the real outbox file. It covers an event delivered to a busy parent at its next turn without a reconnect, a shell read of the outbox that leaves the event unread, a read event that a restarted daemon does not replay, and a backlog delivered oldest first with a late note. `test/integration/fake-socket.test.ts` covers the subscribe acknowledgement, an event buffered ahead of it, `events_lost`, a dropped connection and the request round trip. `test/integration/restart.test.ts` covers a child restart that keeps its child id, a deferred self restart, the refusals, the per-target lock, and a pending restart re-armed when the daemon starts. A client starts its daemon detached, so a case that starts one stops it with `test/fixtures/daemons.ts`, and the last case in `test/integration/claude-channel.test.ts` fails when a daemon is still running after its test.
3. **Lab.** `test/lab/herdr-lab.ts` starts a real herdr server in its own config root and session, with a guard that refuses the live socket. `test/lab/scripted-models.ts` serves an OpenAI-compatible endpoint for Pi and an Anthropic Messages endpoint for Claude, including a stall reply that produces the stuck event. `test/lab/handover-lab.test.ts` hands the daemon over while a child is in a real lab pane, and shows the older session hearing the child's exit from the new daemon. `npm run test:lab` runs it, and the files skip themselves when `herdr` is absent, so CI remains green.
4. **Live smoke.** The same lab with real models at the cheapest tier, run by hand before a release.

A fixture mentions a provider, a model or a tier only when it is public or synthetic. This repository is public, and a name from somebody's own setup stays in its history. A synthetic id starts with `example`, `fake`, `test`, `stub` or `mock`. The public providers and model families sit in `scripts/fixture-identifiers.ts`, each with where it is public, and a new entry needs the same proof.

`test/unit/fixture-identifiers.test.ts` and the `fixture identifiers` step in CI enforce the rule. A failure prints the file, the line and the value with all but its first and last characters hidden, because a CI log is public too.

Scripted replies for each parent and child pair come next. The fixtures exist, and the work left is the orchestration that starts Pi and Claude in a lab pane.

The lab removes `HERDR_ENV`, `HERDR_PANE_ID` and `HERDR_SOCKET_PATH` from the child environment, because inherited values point at the live server. It refuses to start when the resolved socket is `~/.config/herdr/herdr.sock`. The lab root is under `/tmp`, because macOS caps a Unix socket path at 104 bytes and a root under the default temp directory exceeds that cap.
