A child that comes back no longer carries fields from its previous run, because a resume, a restart, an adopted session that returns to its pane and a crossing that a restarted daemon finishes now clear the same fields, from one table. Before this change, a resumed child kept the lost answer of a restart on another machine, and when that machine handed the answer over later, the parent's daemon wrote the old restart's pane over the resumed child. A crossing found running at its destination kept the source run's `reportPending` and `harnessSeenAt`, so the first turn there did not raise an `idle` event and the watcher skipped its check for a harness that exits at once. A resumed or returning child kept the `paneEnd` of the pane it left, so after `agent_stop` ended the new run, `agent_list` and `bellwether doctor` described that older pane. A resume that fails now puts the whole record back, where before it dropped `restartFailed` and `crossingFailed` and `bellwether doctor` stopped reporting a child that still ran nowhere.
